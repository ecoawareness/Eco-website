Step 01 · The big idea

What is a slash command?

When you're chatting with Claude Code in your terminal, a line that starts with / isn't a message to the AI — it's an instruction to the tool itself. Think of it as three everyday things you already know:

A shortcut

One keystroke triggers an action that would otherwise take a paragraph of explanation — like /clear to wipe the conversation or /model to switch models.

A control panel

Commands manage the session: context, permissions, memory, MCP servers, and config — the knobs Claude can't change by chatting.

A reusable prompt

You can invent your own commands. Save a prompt as a file, and /your-command replays it any time — for your whole team.

Step 02 · Read one at a glance

The anatomy of a command

Every slash command has the same simple shape. Here's a custom command being run with an argument:

/triggerfix-issuecommand name 1234arguments

The slash says "this is a command." The name picks which one. Anything after a space is passed in as arguments the command can use.

Step 05 · The superpower

Build your own commands

This is what separates casual users from power users. Drop a Markdown file in .claude/commands/ and its filename becomes a command. Here are three real examples, from simplest to most powerful.

.claude/commands/explain.md
# A plain prompt — the whole file is the instruction
Explain how the code I just shared works,
step by step, as if teaching a beginner.
Keep it under 200 words.

A. The simplest possible command

No setup, no syntax. The filename explain.md creates the command /explain. Running it sends the file's text to Claude as your prompt.

  • Saved in the project → teammates get /explain too
  • Save it in ~/.claude/commands/ instead to keep it personal across all projects
.claude/commands/fix-issue.md
---
argument-hint: [issue-number]
description: Find and fix a GitHub issue
---
Find issue #$1 in our tracker, reproduce
the bug, fix it, and write a test that
covers it. Summarize what you changed.

B. Adding arguments & metadata

The block between --- lines is frontmatter — optional settings. Run it with /fix-issue 1234.

  • $1, $2… grab arguments by position
  • $ARGUMENTS grabs everything after the command at once
  • argument-hint shows expected input in the autocomplete menu
  • description is the one-liner shown next to the command
.claude/commands/review-pr.md
---
allowed-tools: Bash(git diff:*), Bash(git log:*)
description: Review my uncommitted changes
model: claude-opus-4-8
---
## Context (runs before Claude reads this)
Current diff: !`git diff HEAD`
Style guide: @docs/style.md

## Your task
Review the diff above against our style
guide. Flag bugs first, then nits.

C. Pulling in live context

The real magic: feed Claude fresh data before it even starts thinking.

  • !`command` runs a shell command and pastes its output into the prompt
  • @path/to/file drops a file's contents in as a reference
  • allowed-tools pre-approves exactly which shell commands may run — no permission pop-ups
  • model forces a specific model just for this command
